# Source indexes for Markdown and MDX

An indexer needs section text and the locations of real MDX elements. A source search also matches examples in fenced code, inline code, attributes and module strings. For each element, expose half-open UTF-16 offsets into the original JavaScript string. Return the complete element range, including its closing tag when present. The caller can slice the original spelling with those offsets. Index Markdown-level JSX elements in authored source order. JavaScript inside expressions is opaque to this API. Reject malformed MDX with the original diagnostic. Keep framework-specific visibility decisions in the caller.

Use the Rust parser for structural MDX, convert byte offsets to UTF-16 in a single pass, and use the portable reference parser for inputs whose JavaScript requires full validation. The docs integration can apply the index to static wrappers when all candidate tags are accounted for and use its existing visitor for its extended dialect and expression semantics. Reuse the same discovery for adjacent human and agent projections. Public arrays remain owned by their caller and a source edit always invalidates reuse.

Fenced code has different indentation rules across Markdown, MDX and framework renderers. Provide parser-defined fences with language, metadata and source ranges. For search indexing, expose readable text extracted from parsed Markdown, with an explicit choice about including code. Compare these generic capabilities independently of docs-specific rendering and ranking. Verify headings, components, diagnostics and ranges on both runtimes, real docs output, clean npm installation, strict TypeScript, and a benchmark with identical-baseline controls.
